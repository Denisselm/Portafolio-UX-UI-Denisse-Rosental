Outlife Intranet — Diseño de sistema interno desde cero

Diseñé desde cero la experiencia UX/UI de un sistema interno utilizado por distintas áreas de la empresa, creando flujos, componentes y patrones consistentes para facilitar tareas operativas complejas.

Plataforma utilizada por operaciones, marketing, administración y gerencia para gestionar clientes, ventas, productos y tareas administrativas. El proyecto incluyó arquitectura de información, diseño de flujos, diseño visual, design system y seguimiento de implementación.

Contexto y problema

Outlife contaba con una intranet funcional, pero con múltiples inconsistencias entre módulos. La interfaz tenía poca jerarquía visual, patrones distintos según cada sección y ausencia de feedback claro en acciones importantes.

Esto generaba confusión en tareas frecuentes y hacía que muchos usuarios dependieran de compañeros para validar procesos o encontrar funcionalidades específicas. Según feedback entregado por el líder de proyecto, los usuarios nuevos necesitaban acompañamiento frecuente durante sus primeros días utilizando el sistema.

Sistema original utilizado por distintas áreas de la empresa.

Patrones inconsistentes entre módulos

Cada módulo funcionaba de manera distinta, dificultando el aprendizaje y obligando a los usuarios a reaprender acciones frecuentes.

Procesos operativos fragmentados

Algunas validaciones y revisiones se realizaban fuera de la plataforma, generando dependencia entre equipos y pérdida de tiempo operativo.

Poco feedback del sistema

El sistema entregaba poca información sobre errores, estados o confirmaciones, lo que generaba incertidumbre al ejecutar ciertas acciones.

Investigación

Realicé entrevistas con usuarios de operaciones, marketing, administración y gerencia para entender cómo utilizaban el sistema en su trabajo diario y detectar los principales puntos de fricción.

Complementé esto con revisión de flujos existentes y evaluación heurística para identificar inconsistencias de navegación, problemas de feedback y diferencias de comportamiento entre módulos.

Síntesis de observaciones obtenidas durante entrevistas y revisión de flujos.

Hallazgos recurrentes

Los usuarios mencionaban dificultades para encontrar acciones, diferencias de comportamiento entre módulos y falta de claridad al completar tareas frecuentes.

Insight principal

Aunque el sistema cumplía funcionalmente, la falta de consistencia hacía difícil aprenderlo y utilizarlo con seguridad entre distintas áreas.

Contexto de trabajo

Trabajé de forma remota como responsable UX/UI del proyecto, colaborando directamente con el líder de proyecto y el equipo de desarrollo externo.

Las prioridades iban cambiando según necesidades del negocio, por lo que el trabajo se desarrolló de manera iterativa, avanzando módulo por módulo.

Diseño de flujos y pantallas

Diseñé flujos, wireframes e interfaces en Figma, documentando funcionalidades y comportamiento de componentes.

Trabajo con stakeholders

Participé en reuniones y dailies con el líder de proyecto para revisar avances, resolver dudas y priorizar funcionalidades.

Design QA

Revisé implementaciones desarrolladas para detectar inconsistencias visuales o funcionales respecto a los diseños entregados.

Seguimiento de implementación y revisión de inconsistencias durante desarrollo.

Antes vs Después

El objetivo del proyecto fue generar una experiencia más consistente, clara y fácil de utilizar entre los distintos módulos del sistema.

Antes

  • Poca jerarquía visual en tablas y formularios
  • Patrones distintos entre módulos
  • Acciones difíciles de identificar
  • Poco feedback del sistema
  • Mayor dependencia entre usuarios

Después

  • Mayor claridad visual y organización de información
  • Patrones más consistentes entre módulos
  • Acciones visibles y mejor organizadas
  • Validaciones y mensajes más claros
  • Flujos más fáciles de aprender

Decisiones de diseño

Las decisiones de diseño se enfocaron en reducir inconsistencias, mejorar la claridad de uso y facilitar tareas frecuentes dentro del sistema.

Patrones consistentes entre módulos

Definí estructuras similares para tablas, formularios y acciones frecuentes, buscando que los usuarios pudieran reconocer patrones comunes entre distintas áreas del sistema.

Mayor consistencia visual y reducción de fricción entre módulos.

Validaciones y feedback más claros

Incorporé mensajes de error, estados y validaciones visibles para ayudar a los usuarios a identificar problemas antes de continuar ciertos procesos.

Mejor comprensión de errores y estados dentro de formularios.

Jerarquía visual y organización de acciones

Reorganicé información, acciones y prioridades visuales para facilitar el escaneo rápido de datos y mejorar la lectura de tablas y módulos administrativos.

Mayor claridad visual en tareas operativas frecuentes.

Adaptación entre dispositivos

El sistema necesitaba responder a distintos contextos de uso, manteniendo consistencia visual y priorizando tareas diferentes según cada dispositivo.

Desktop

Diseñado para gestión intensiva de datos, tablas complejas y tareas administrativas.

Tablet

Adaptado para supervisión y revisión rápida de información operativa.

Mobile

Enfocado en consulta rápida y acciones esenciales en contexto de movilidad.

Design system

El proyecto no contaba con un sistema de diseño previo, por lo que construí una librería de componentes base en Figma para mantener consistencia visual y funcional entre módulos.

Componentes reutilizables

Definí componentes para tablas, formularios, botones, estados y modales utilizados a lo largo del sistema.

Consistencia entre módulos

La librería permitió mantener comportamientos similares entre distintas áreas y facilitar nuevas iteraciones.

Base para escalabilidad

El sistema quedó preparado para continuar agregando módulos y funcionalidades de forma más ordenada.

Componentes y estilos utilizados en distintos módulos del sistema.

Resultados y aprendizajes

Los primeros módulos implementados recibieron feedback positivo respecto a claridad visual, organización de información y facilidad de uso en tareas frecuentes.

Lo que funcionó

La estandarización de patrones y componentes ayudó a generar una experiencia más consistente entre módulos y facilitó la colaboración con desarrollo.

Lo que haría distinto

Si volviera a desarrollar el proyecto, definiría métricas de uso desde el inicio para medir con mayor precisión el impacto de las decisiones de diseño.
